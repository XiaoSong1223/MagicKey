# MagicKey

给 MacBook 内置键盘背光加上动态效果的 macOS 菜单栏应用。

呼吸、心跳、频闪、按键脉冲，亮度范围和周期可调，空闲时自动停止并还原你原来的设置。

```bash
cd app && make install
```

菜单栏会出现键盘图标——运行时实心，停止时线框。

---

## 先说清楚做不到什么

**不能变色，不能单键控制。** 这是硬件限制，不是软件没做到。

MacBook 内置键盘的全部 LED 共用一路 PWM 通道，只有一个 0–255 的全局亮度寄存器。
`root` 权限、内核驱动、私有 API 都不能凭空产生不存在的红绿蓝。

所以 MagicKey 的全部创作空间是**一个数值随时间的变化**——这既是限制，
也是整个架构的组织原则（见 [`DESIGN.md`](DESIGN.md)）。

想要真正的 RGB 只能换外接键盘。

## 要求

- macOS 14+
- Apple Silicon（Intel 机型未测试）
- 带背光的内置键盘

## 几个实测得到的约束

完整记录在 [`DESIGN.md`](DESIGN.md)，这里列最反直觉的三条：

**255 档是设计约束，不只是精度问题。** 整条效果曲线只有 255 个可用值，
且余弦在转折点导数为零会天然停留。单档停留超过约 100ms 肉眼就能察觉为卡顿。
评估效果要看「档位停留时长分布」，不是看曲线画得好不好看。

**不要做 gamma 感知映射。** 任何 γ>1 都会把暗段压进 0–2 档。γ=2.2 时单档停留 167ms、
每周期还会完全熄灭 150ms。Apple 的 0–1 很可能已经做过感知映射了。

**60fps 已触及硬件地板。** 4s 呼吸在 60fps 下最差处仅跳 1 档，物理上不可能更小——
90fps、120fps 没有任何改善。想让低亮度段更平滑，抬高亮度下限比堆帧率有效一倍。

## 私有 API

亮度控制走 `CoreBrightness.framework` 的 `KeyboardBrightnessClient`，这是私有接口。

- 不静态链接，`dlopen` + 逐个 selector 探测
- 探测失败则整体降级，UI 显示「不受支持」而不是崩溃
- 因此**不能上 Mac App Store**（违反 App Review Guidelines 2.5.1）

好消息是它不需要 root，普通用户权限即可读写。

## 状态

v0.1。呼吸/心跳/频闪/常亮/按键脉冲、参数调节、空闲即停、开机自启已经可用。

按键脉冲**不需要输入监控权限**：只读取「距上次按键多少秒」这一个标量
（`CGEventSource.secondsSinceLastEventType`，公开 API），拿不到也不需要 keycode——
内置键盘全部 LED 共用一路 PWM，「按了哪个键」无处可用。
同理，**灯光无法以按下的键为中心向四周扩散**，只能整块键盘一起亮。

尚未做：CLI/URL Scheme 触发、音频律动、应用图标、代码签名与公证。
