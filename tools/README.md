# MagicKey 开发工具

调效果曲线和测能耗用的命令行工具。与 app 共用 `../Core/`，所以分析结果和实际渲染
不会漂移——这是它做成二进制而不是独立脚本的唯一理由。

```bash
make            # 构建 magickey-tool
make analyze    # 分析默认呼吸曲线
make preview    # 在真实键盘上预览，Ctrl-C 停止并还原
```

## 三个模式

```bash
./magickey-tool --analyze --effect breathe --period 4 --min 0.05
./magickey-tool --preview --effect heartbeat --period 1.2
./magickey-tool --set 0.45          # 一次性设置亮度，不还原（能耗测量用）
```

`--preview` 覆盖了完整的还原路径：Ctrl-C、SIGTERM、系统睡眠、崩溃后重启。

## 效果曲线分析器

调效果时用它替代肉眼试错。输出两项判据：

**1. 卡顿检查** —— 单档停留 >100ms 即标记。阈值由实机观察反推：
gamma 2.2 造成的 178ms 停留肉眼可见，83ms 无人察觉。

**2. 帧率需求** —— 判据是**最大相对亮度步进**（韦伯定律），不是丢档比例。
高亮度区跳 3 档只有 2% 变化看不出来；档位 2 附近跳 3 档是 150%，一眼可见。

声明为 `.punctuated` 的效果（心跳、频闪）只输出描述性数据、不给结论——
它们的突变和保持是设计本意，用连续渐变的判据评判是错的。

### 已知结论（4s 呼吸）

| | |
|---|---|
| 60fps | 已触及硬件地板（最差处仅跳 1 档），**90/120fps 无任何改善** |
| 30fps | 从 7.7% 劣化到 12.5%，省电模式降频可行 |
| 亮度下限 | 比帧率有效得多：`--min 0.15 @60fps` = 3.9%，优于 `--min 0.05 @120fps` = 7.7% |
| gamma | **保持 1.0**。任何 >1 都会把暗段压进 0–2 档产生可见卡顿 |

## 能耗与睡眠测试

见 [`TESTING.md`](TESTING.md)，含一次失败的测量和它的诊断——
整机电池读数分辨不出几十 mW 的软件成本，必须改用 CPU 功耗。

配套脚本：

- `measure-power.py` —— 电池放电功率采样（需拔电源）
- `measure-cpu-power.sh` —— CPU 封装功耗采样（需 sudo）
